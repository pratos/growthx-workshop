The domain vocabulary for a multiplayer coding agent

2026-10-28 · draft · pratos with Claude Code · 4 min read · built from docs/plans/2026-10-28-domain-vocabulary.plan.json

Greenhouse has words for planning, but none for the agent's work, the live room, or the workspace. This plan names them in the domain vocabulary and packages/schema: pi-durable's words for agent work, Amp's Thread for a conversation with the agent, and Comment for today's comment thread.

Where we are

Eight nouns across two contexts; two definitions contradict themselves and three schemas are missing. The stack's own words collide: session means six things, pi-durable's agent is a configuration, and Amp's thread is our comment thread.

  • Plan is "a document" while banning document, and four event verbs are missing from the verb list (docs/DOMAIN-VOCABULARY.md:28,51).
  • rationale is read by the upcaster but named nowhere else (packages/domain/src/upcast/index.ts).
  • Chopin says document for the product, Plan only on a tab, comment in its interface and finding for research results.
  • pi-durable's run is one input to its final answer: what people mean by the agent is running.
  • Appleton's own terms are boundary objects and interactive report. The pattern labels on our workshop page are ours, not hers.

Where we end up

One domain vocabulary with four contexts, an adopted-words table pinned to pi-durable 1.4.0, a schema per noun, a check that enforces all of it, and a map of the vocabulary. After the workshop, the code says Comment.

Not doing

  • Implementing Runs, Rooms or Workspaces; this plan only names them.
  • Renaming kernel words like Decider and Message; they stay internal.
  • Copying Chopin's identifiers; we borrow only the words users already say.
  • Rewriting the workshop page beyond the Appleton attribution.

Approach

Fix the domain vocabulary's mistakes first. Then add contexts, words and schemas, make the check enforce them, and render the map. Renaming code and stored events waits until after the workshop.
