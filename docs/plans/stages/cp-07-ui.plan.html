UI and UX with Impeccable, Emil Kowalski's skill and Agentation

cp-07 · 2026-10-28 · final · pratos with Claude Code · 3 min read · built from docs/plans/stages/cp-07-ui.plan.json

The plan page and sessions panel work but read as a wireframe. This stage gives them one component language from the theme tokens, a top bar that names you, and clear empty and decided states. The process is the lesson: Impeccable critiques, Emil's animate decides motion, Agentation carries notes.

Where we are

cp-06 ends with the plan page (threads ending in decisions), sessions in a chat panel beside it, and just agent-serve answering through pi-durable. The screens use grey Tailwind defaults, the top bar always says Sign in, and the as field starts as pratos whoever signed in.

  • apps/web/src/styles.css already defines light and dark tokens (--sea-ink, --lagoon, --surface, --line); classes built on them hold in both themes.
  • PRODUCT.md and DESIGN.md describe the workshop deck, not the app; the critique works from the app's tokens.
  • Agentation mounts in DevTools.tsx behind import.meta.env.DEV, and .mcp.json runs agentation-mcp, so notes reach the agent.
  • The warn tone #b45309 reads 3.7:1 on the dark background, under AA for small text: a good first note.
  • A Sign out in the top bar makes two on /; signOut in e2e/helpers.ts must scope to header-account.

Where we end up

/plans/gh-12 in dark mode, before and after: cards, one lagoon action per form, pills for counts and live, bubbles that settle in once. The top bar names you; acting as starts as you. One Agentation note fixed live.

Not doing

Out of scope for this plan, each with the reason in the same line.

  • A new palette or font; the tokens and Manrope stay.
  • Showing failed runs; the bubble is styled here, RunFailed arrives in cp-08.
  • Motion on refresh, hover lists or the top bar; arrival only.
  • A mobile layout beyond the one-column fallback under lg.

Approach

Critique first, on the running cp-06 page, so findings set the work. Then classes, which every screen uses; then the top bar, which changes behaviour; then page and panel. Agentation notes close it.

Decisions

Each real choice in this plan, with the options compared side by side. A decided one is locked on its choice; open “Compare the options” to see why.

Animate new messages?

Chosen: Yes, once, on arrival: 180ms opacity and a 4px lift · pratos · 2026-10-28

Emil's frequency gate: messages arrive a few times an hour, so a 180ms settle helps the eye find what is new. Replayed on every refresh it is noise. Off under reduced motion.

Design language

The look this plan’s screens use: tokens first, then each component rendered live in every state it can be in.

The plan page is an Operate surface, read often by people working together. Quiet cards from the theme tokens; one lagoon accent marks the action you can take; palm only for live and decided; amber only for what failed.
