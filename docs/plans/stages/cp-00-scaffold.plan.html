Scaffold and skills, running locally

cp-00 · 2026-10-28 · final · pratos with Claude Code · 3 min read · built from docs/plans/stages/cp-00-scaffold.plan.json

A fresh clone runs two Workers with one command, before any product exists. This stage lays the ground every later stage and every agent stands on: the layout, a pinned toolchain, the recipes, the lint boundary, the skills and hooks, and the architecture map.

Where we are

An empty repository. This is the first stage, so there is no earlier branch; nothing here is specific to Greenhouse yet.

  • apps/web/vite.config.ts runs the API as an auxiliary Worker, so one vite dev serves both and the API binding works locally.
  • The web Worker reaches data only through env.API, calling https://api/<path>; apps/web/src/lib/api.ts is the one place that does it.
  • /healthz carries two versions: label from the GIT_DESCRIBE var for people, id from the VERSION metadata binding for wrangler rollback.
  • bun scripts/arch.ts --coverage refuses any folder under apps/ or packages/ that the doc's "Where it lives" table does not name.
  • just agent-ready checks files and recipes, never judgement; here it reports gaps for just seed, seeded accounts, test logins, sign-in and an admin route.

Where we end up

On a fresh clone, just up serves http://localhost:3000. Its /healthz shows the web and api versions, the api's fetched through the binding; /readyz reaches D1. just agent-ready lists what is still missing, honestly.

Not doing

Out of scope for this plan, each with the reason in the same line.

  • Deploying anywhere; cp-01 adds the deploy script, CI and rollback.
  • Domain words, events or accounts; cp-02 names them and cp-03 builds them.
  • Tables; the D1 binding exists, but no migration does until cp-03.
  • Product pages; the web app serves health and a placeholder home page only.

Approach

Toolchain first, so every later command is the same on every laptop. Then the two Workers and their health. Then the guard rails that keep later stages honest: the lint boundary, the map, the hooks.

Decisions

Each real choice in this plan, with the options compared side by side. A decided one is locked on its choice; open “Compare the options” to see why.

Where does the web Worker get its data?

Chosen: Through the API binding only · pratos · 2026-10-28

One door means one place for sign-in, flags and rules. The lint makes a database import under apps/web an error, so the choice holds when an agent is in a hurry.

Phase 1 Toolchain: one shell, one set of recipes

not started · 0/3

nix develop gives the same tools on every laptop and sandbox; just install installs and links every skill; just --list shows this stage's recipes.

Changes

Each file this phase touches and what must be true of it afterwards. Code appears only as a contract other code depends on.

  • flake.nix
    A devShell with bun, nodejs_24, just, jq, curl, git and uv; node_modules/.bin on PATH.
  • flake.lock
    Committed, so every clone resolves the same nixpkgs.
  • package.json
    Bun workspaces apps/* and packages/*; wrangler, oxlint and typescript pinned as dev dependencies.
  • tsconfig.base.json
    Strict compiler settings that every app and package extends.
  • .gitignore
    Covers node_modules, dist, .wrangler and .dev.vars*, the entries just agent-ready checks.
  • justfile
    Every runnable thing is a recipe, quiet on success; just alone lists them.
  • AGENTS.md
    The rules no lint can hold, as on main; CLAUDE.md is a symlink to it.
  • docs/WORKFLOW.md
    One task end to end in nine steps, each with who and the recipe.

Phase 2 Two Workers, joined by the API binding

not started · 0/4

just up runs both Workers locally. Each answers /healthz and /readyz; the web Worker's answers include the api's, fetched through the binding.

Changes

Each file this phase touches and what must be true of it afterwards. Code appears only as a contract other code depends on.

  • apps/api/wrangler.jsonc
    greenhouse-api with the DB D1 binding, VERSION metadata and GIT_DESCRIBE defaulting to dev.
  • apps/api/src/index.ts
    A Hono app with the two health routes and a JSON 404.
  • apps/web/wrangler.jsonc
    greenhouse-web on the TanStack Start server entry, with the API service binding.
  • apps/web/vite.config.ts
    The Cloudflare plugin runs ../api/wrangler.jsonc as an auxiliary Worker beside the web app.
  • apps/web/src/lib/api.ts
    apiGet(path) fetches https://api<path> through env.API; the only route to data.
  • apps/web/src/routes/healthz.ts
    Answers with this Worker's version and the api's /healthz, or the error reaching it.
  • apps/web/src/routes/readyz.ts
    200 only when the api's /readyz is ok through the binding, else 503.

Phase 3 Guard rails: the boundary, the map, the hooks

not started · 0/5

A database import under apps/web fails just lint. just arch builds the map from the doc. Hooks rebuild it on edit and print agent-ready gaps.

Changes

Each file this phase touches and what must be true of it afterwards. Code appears only as a contract other code depends on.

  • .oxlintrc.json
    An apps/web/** override bans domain and database imports, citing the architecture doc.
  • docs/ARCHITECTURE.md
    The Mermaid map, walkthrough, "Where it lives" and "Allowed edges" for two Workers and D1.
  • scripts/arch.ts
    Builds docs/architecture/index.html; --coverage and --check fail on an unnamed folder or stale map.
  • skills/manifest.json
    Third-party skills pinned by commit: cloudflare, wrangler, durable-objects, impeccable, animate, stagehand-browse and more.
  • scripts/skills-sync.sh
    just skills: vendor each pinned skill into skills/vendor/, then link every skill for both agents.
  • skills/
    Ours: create-plan, viz-explainer, scaffold, ddd-vocabulary, event-sourcing, agent-ready, slop-guard, accident-or-essence.
  • .claude/settings.json
    PostToolUse runs both hooks on every edit; SessionStart prints the agent-ready gaps.
  • scripts/hooks/arch-hook.sh
    Rebuilds the map or a plan page; refuses, with exit 2, an unmapped app.
  • skills/agent-ready/scripts/hook.sh
    Never blocks; prints open gaps at session start and after edits to files it checks.
