# Layout

One line per folder: what it holds, and what goes there. Read the second table before creating anything.

```
.
├── AGENTS.md / CLAUDE.md     The four rules that cannot be a lint. Same text in both files.
├── justfile                  Every runnable thing. One comment line per recipe; that comment is `just --list`.
├── flake.nix                 The dev shell: bun, node, just, jq, curl, git, uv, sops, age. Wrangler and oxlint come from bun, not nix.
├── package.json              Bun workspaces: apps/*, packages/*. Root devDependencies: wrangler, oxlint, oxfmt, typescript, workers-types.
├── tsconfig.base.json        Strict compiler options every package extends. Never loosened downstream.
├── .oxlintrc.json            Lint config. The apps/web override is the import boundary (no domain, no db client in the web Worker).
├── .mcp.json                 MCP servers the agent may use locally (slop-guard).
├── .github/workflows/
│   └── deploy.yml            One workflow: check (lint, test, types current, migration guard), preview (PR: versions upload, no traffic), deploy (main: scripts/deploy.sh + smoke), migrate (manual trigger only).
├── apps/
│   ├── api/                  Hono Worker `greenhouse-api`. /healthz, /readyz, /plans/:id/commands, events, read model. PlanRoom Durable Object.
│   │   ├── src/index.ts      Routes and loadFlags(). Flags are read here and passed to the DO as names.
│   │   ├── src/plan-room.ts  The Durable Object: one per Plan, SQLite event log, dispatch() appends in one block.
│   │   ├── migrations/       D1 migrations, NNNN_name.sql. Additive. Applied by hand or the manual CI job, never on deploy.
│   │   ├── wrangler.jsonc    Bindings as config: D1 `DB`, DO `PLAN_ROOM`, `VERSION`, var `GIT_DESCRIBE`, observability.
│   │   └── worker-configuration.d.ts  Generated by `wrangler types`. Committed. CI fails if stale.
│   ├── web/                  TanStack Start Worker `greenhouse-web`. Talks to the API over the `API` service binding only.
│   │   ├── src/routes/       File routes. __root.tsx, index.tsx, login.tsx (public), healthz.ts (server handler), plans.$planId.tsx.
│   │   ├── src/lib/api.ts    The only path to data: apiGet / apiCommand over env.API.
│   │   ├── src/components/   Header, Footer, ThemeToggle, DevTools (Agentation toolbar, dev only).
│   │   ├── vite.config.ts    cloudflare plugin runs the api as an auxiliary Worker so `just up` is one process.
│   │   └── wrangler.jsonc    `services: [{ binding: API, service: greenhouse-api }]`, `VERSION`, `GIT_DESCRIBE`, observability.
│   └── checkin/              Standalone Worker for the workshop check-in (growthx-eng.tarp.sh). Own D1, own domain, `just checkin dev|deploy`. Imports nothing from packages/.
├── packages/
│   ├── schema/               The domain vocabulary as types (zod today). Imported by domain and web. Depends only on zod.
│   ├── domain/               The decider: kernel.ts, thread/decider.ts, upcast/. Expect tests and __expect__/ snapshots. No I/O.
│   └── db/                   seed.sql (local admin + random user, flags off). Migrations are NOT here; wrangler wants them under apps/api/migrations.
├── scripts/                  What recipes call when they outgrow one line: deploy.sh, new.sh, flag.sh, replay.sh, review.sh, demo.sh, skills-sync.sh.
├── skills/                   Skills loaded by Claude Code and pi. Ours in skills/<name>/, vendored in skills/vendor/ (gitignored, pinned in manifest.json).
├── tools/
│   ├── twelve-factor-baml/   Twelve-factor checker in BAML. `baml run main -- <service path>` from that folder.
│   └── slop-jev/             The Jev prose scorer binary source.
├── docs/
│   ├── DOMAIN-VOCABULARY.md           The vocabulary. A noun is here before it is in code.
│   ├── ARCHITECTURE.md       The diagram and the allowed-edges table. Update in the same commit as a new edge.
│   ├── RELEASE.md            Release checklist: flag off at deploy, you first, slice, percentage, rollback path.
│   ├── CHECKPOINTS.md        Workshop tags cp-00..cp-07 and the demo.sh beat for each.
│   ├── RUNBOOK.md            Live URLs, commands typed on stage, what to do if something is on fire.
│   └── decisions/            viz-explainer artifacts (HTML + spec.json). No Markdown explainers.
├── repos/effect              Vendored Effect source, read-only reference. Not present in every checkout; if absent, do not fetch it, read the `effect` package docs.
└── deck/ workshop-page/ memes/ demo/   The talk. Not part of the product; not linted.
```

## Where a new thing goes

| New thing | Where | Then |
|---|---|---|
| Worker | `apps/<name>/` with `wrangler.jsonc`, `src/index.ts`, `package.json`, `tsconfig.json`, `worker-configuration.d.ts`. Only when it needs its own deploy, domain or dependencies; otherwise it is a route. | `references/new-worker.md`. Row in the ARCHITECTURE.md edges table. Row in the README table. |
| Package | `packages/<name>/` with `package.json` (`@greenhouse/<name>`, `exports: { ".": "./src/index.ts" }`) and `src/index.ts`. Extend `tsconfig.base.json`. Domain-side packages have no I/O. | Edge row in ARCHITECTURE.md. Lint override if a Worker must not import it. `just test` already covers `packages`. |
| API route | `apps/api/src/index.ts` until it is long; then `apps/api/src/routes/<area>.ts` mounted with `app.route()`. Hono handler in front, Effect behind. | Domain vocabulary word for any new noun in the path. A command route goes through `dispatch`, never writes events itself. |
| Web route | `apps/web/src/routes/<name>.tsx` (page) or `<name>.ts` with `server.handlers` (endpoint). `routeTree.gen.ts` regenerates; do not edit it. | Data only through `#/lib/api`. Public pages are `/login` and `/healthz`; everything else sits behind auth once it lands. |
| Command or event | `just new command Name` / `just new event Name` after the domain vocabulary entry. Lands in `packages/domain/src/thread/decider.ts` with an expect stub. | `event-sourcing` skill. Flag question first; the flag check goes in `decide()`. |
| Migration | `apps/api/migrations/NNNN_name.sql`, next number. Additive only. | `just migrate-local`. Seed rows in `packages/db/seed.sql`. Apply to remote by hand before deploying the code that needs it. |
| Flag | A row in the `flags` table via `just flag off NAME` (local) / `GH_REMOTE=1 just flag off NAME` (prod). No code file. | Seed it off in `seed.sql` if local dev needs the row to exist. |
| Recipe | The justfile, with a comment line. Script in `scripts/<name>.sh` if over a few lines, `set -euo pipefail`, ends with a `Next:` line. | Mention it in RUNBOOK.md "Commands you will type" if a person runs it on stage. |
| CI job | `.github/workflows/deploy.yml`. A job runs the same `just` recipe or script a person runs; no logic that exists only in YAML. | Secrets through repository secrets, never in the file. |
| Secret | `.dev.vars` via `just secret put NAME` locally; `bunx wrangler secret put NAME` for a deployed Worker (run by the person). | Reference it in code only through `env`. Never a default value in `vars`. |
| Skill | `skills/<name>/SKILL.md` with frontmatter `name` and `description`, sections When this fires / Rules / Build sequence / Reference, `references/` for the long parts. | Row in `skills/README.md`. `just skills` links it into `.claude/skills` and `.pi/skills`. |
| Decision or explainer | `docs/decisions/<name>.spec.json` built to `.html` with `just artifact`. | `viz-explainer` skill. No Markdown write-up. |
